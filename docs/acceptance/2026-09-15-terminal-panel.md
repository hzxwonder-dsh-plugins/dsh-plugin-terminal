## 三、缺陷与修复

本次评测共发现并修复 4 个缺陷，均已在同一版本内完成修复与回归。

### 缺陷 1（严重）：已退出的终端会让 DSH Host 进程崩溃

- 现象：shell 执行 `exit` 之后，客户端重新挂载终端时会向已退出的会话发一次 `resizeTerminal`，
  Host 进程随即以 SIGABRT 退出（应用日志 `DSH Host exited (6)`），界面从此失去后端。
- 最小复现：`POST /api/dsh-terminal {"action":"resizeTerminal","terminalId":"<已退出会话>"}`。
- 触发路径：`exit` 关闭 shell（H5）→ 刷新页面或收起再展开面板（H9 场景），
  此时 `fit()` 在新的 xterm 上量出尺寸并同步给已经结束的 pty。
- 修复：`remote.js` 的 `resize()` 对已关闭/已退出的会话直接返回 `{resized:false}`，不再触碰 pty 句柄；
  `client.js` 的 `fit()` 在首帧写入之前或会话已退出时不再发尺寸请求。
- 验证：同一请求由「Host 崩溃」变为 `{"resized":false}` 且 Host 保持在线；
  H5 → H9 的连续序列不再崩溃（本报告 H5/H7/H8/H9/H13/H14 全绿）。
- 单测：`test/remote.test.js` 新增「an exited session never reaches the pty handle again」，
  套件 15 项全通过。

### 缺陷 2：已退出的终端仍显示「已连接」，且逐键刷新英文错误

- 现象：shell 退出后标签仍是运行态圆点，右侧状态标签仍显示「已连接」，
  每按一个键就发出一次必然被拒的写入请求，状态栏出现 `REMOTE_TERMINAL_SESSION_CLOSED` 并随按键闪烁。
- 修复：会话退出后标记为已退出——标签圆点转灰、状态栏显示「终端已退出」、右侧标签显示「已退出」，
  输入被忽略且不再发出请求。
- 验证：H13（向已退出终端输入后新增错误 0）、H14（右侧标签=已退出）、H5（状态栏文案）。

### 缺陷 3：切换标签后画面不重绘（空白或停在旧内容）

- 现象：在多个终端之间来回切换后，当前终端可能显示空白或上一次的旧画面；
  输入其实已经送达，但看不到回显，表现为「切回来就不能输入」。
- 原因：被隐藏（`display:none`）的终端停止绘制，重新显示时 xterm 保留的行不会自动重绘，
  只有尺寸变化才会顺带刷新。
- 修复：终端重新显示时主动调用一次 `refresh()`，不依赖尺寸变化。
- 验证：C/D 两组 14/14；D2（切换后可输入）、D3（切回后可输入）、D4（两个终端画面互不串台）由失败转为通过。

### 缺陷 4：新建与关闭竞态会留下无人管理的终端元素

- 现象：快速交替点「+」和「×」之后，视图里会多出一个不属于任何标签的终端元素。
  它没有盒子上的 `display:none`，所以仍然算「当前终端」：真正的终端被挤到视图下方看不见，
  面板看起来是空白或停在旧画面，按标签读到的内容也可能来自这个幽灵元素。
- 原因：新建请求返回后 xterm 资源是异步加载的，若在这段时间里该标签被关闭，
  关闭路径找不到尚未建立的实例，而加载完成后仍然照常创建并挂载。
- 修复：加载完成后再核对标签是否仍存在，不存在就不创建；每次重挂时清掉视图里
  不属于任何在册终端的多余元素。
- 验证：H2（交替快击后标签数=xterm 元素数，1 秒内收敛）、D1（6 个标签恰好 1 个可见元素）、
  A12（收起再展开后恰好 1 个元素）；修复前同一用例出现 `标签=3 xterm=4` 不收敛。

## 四、未覆盖项与限制

### 4.1 本次未覆盖的行为

- H6 外部杀掉面板自身的远端 ssh 进程：需要一个可被外部终止的独立 ssh 进程，本机工作区不成立。
- H10 以「控制台新增错误 = 0」的形式在每轮统一判定，没有单独一项。
- G6 工作区不可用（目录被删/权限丢失）：评测期间没有构造出安全的不可用工作区。
- 只读会话的工作区策略：只验证了面板在只读工作区不发送尺寸请求，未逐一验证输入拦截提示。
- 输入法（中文候选窗）、括号粘贴（bracketed paste）、TUI 的鼠标上报、macOS 组合键（如 Cmd+K）：
  需要真实键盘与输入法，DevTools 注入的按键无法覆盖。
- agent 侧终端工具（`terminal_exec` 等非面板部分）不在本次范围。

### 4.2 实测到的性能边界

- 10 万行输出（约 590 KB）：本轮 PTY 侧 707ms、屏幕 715ms；多次实测在 0.5–1.5 秒之间
  （面板可见、scrollback 已满、本机工作区）。
- scrollback 已满时，单条命令的回显延迟约 1.0–1.2 秒；新建终端上约 0.1–0.3 秒。
  评测脚本因此按「等待回显」判定，而不是固定延时。
- 在输出风暴尚未渲染完时用键盘输入下一条命令，其执行会被推迟（实测数十秒），
  渲染完成后立即恢复正常；这期间面板本身仍可操作（H1–H4 全绿）。
  该数字包含评测工具自身的开销：键盘输入由 DevTools 协议逐字符注入，主线程繁忙时注入同样被拖慢，
  因此方向确定、量级偏高。

### 4.3 评测自身的边界

- 断言来自面板 DOM、`/api/dsh-terminal` 返回和局部截图，属于界面层证据，
  不能替代真实键盘、输入法和真实远端网络下的手工体验。
- 截图仅截取面板及其周边区域，避开侧栏的会话内容。
- 评测在被测应用的真实会话里进行，会留下若干本机终端与测试用远端终端。

### 4.4 长时运行的观察（未定位根因）

同一应用实例上连续跑多轮评测（每轮创建并关闭约 10 个终端）之后，出现过这样的状态：
终端显示提示符，但键盘输入与直接写入都不再被 shell 执行，`readTerminal` 里也看不到新输出；
重启宿主后立即恢复，全新实例上单轮跑完全部用例不复现。
这与 pty 及其子进程在关闭时的回收有关，本次只记录现象与复现条件，没有定位到根因。
